# リーダブルコード学習

## 第一章　理解しやすいコード
理解しやすいコードとは、他人もしくは未来の自分が、**最短時間で理解できるようなコード**である。  
短いコードが必ずしも理解しやすいコードとなるとは限らない。  
また、それを行うことは**設計や最適化、テストのしやすさなど他の目標と競合しない**。  

## 2章 名前に情報を詰め込む
命名についてのトピック  
1.より明確な単語を選ぶ
get、find、start、makeなどの単語は、単語の持つ意味が抽象的で目的がわかりにくい。  
**そのコードの目的を具体的に反映した名前をつけるべき**だ。  
ただ**日本では他の人や自分自身がその単語の意味を正確に理解しているとは限らない**ため、適度にわかりやすい単語を選ぶべき.  
Ex:
get→fetch、download  
send→deliver、announce  
find→recover、search、extract  
make→create、build、generate、ad  

2.汎用的な名前を避ける
tmpやretval、loop処理のi,j,kなどは、**生存期間が少なく、それ以上の意味がない場合を除いて、付加情報をつけるべき**。  
(tmp_file、member_iなど)

3.優先度が高いものにフォーカスをあてて命名する  
TCP/IPポートをサーバーがリッスンできるかどうかを確認するメソッドは、ポートが大事であるためCanListenOnPort()などとする。
特に、**セキュリティ的に見誤ると多大な被害が発生するような箇所ではそれにフォーカスを当てたい**。  
Ex:  
unescaped_comment、html_utf8、plaintxt_password  

4.名前の長さについて
名前が長いよりは短いに越したことはないが、短すぎても分かりにくくなる。スコープが小さければ短い名前にしても良いが、昨今はエディタの入力補完が優秀なため、そこまで長さは問題にはならない。  
長さを気にするあまり、省略形を使用する場合は、その**省略した単語が一般的に伝わるものであるか吟味するべき。また、言語やプロジェクト特有の規則がある場合はそれに則るべき**。
